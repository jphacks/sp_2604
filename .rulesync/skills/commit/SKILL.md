# コミット

## 手順

1. 差分全体を把握する。
   - `git status --porcelain=v1 -uall`
   - `git diff --cached` (ステージ済み)
   - `git diff` (未ステージ)
   - 未追跡ファイルは中身を読んで確認する。
2. 差分を **セマンティックな単位** に分ける。
   - 1 コミット = 1 つの意図 (機能追加、バグ修正、リファクタ、テスト追加、設定変更など)。
   - 意図の異なる変更が同じファイルにある場合は `git apply --cached` にパッチを渡すなどしてハンク単位で分ける (`git add -p` は対話式なので使わない)。
   - 各コミット時点でビルドが壊れない順序にする (例: Domain → Infrastructure → Application → Presentation → UITests)。
3. 既にステージされている内容もいったん `git restore --staged .` で戻し、分割単位ごとに `git add` し直してからコミットする。
4. 秘密情報 (`.env*`、鍵、トークン、`fastlane/.env` など) が含まれていないことを確認する。含まれていたらコミットせずユーザーに報告する。
5. すべての差分をコミットしたら `git status` が clean であることを確認し、作成したコミットを `git log --oneline` で報告する。

## コミットメッセージ

日本語で書く。

```
<変更内容を簡潔に 1 行で>

- <詳細 1>
- <詳細 2>
```

- 1 行目: 何を変えたかを簡潔に (50 文字程度まで、末尾に句点を付けない)。prefix (`feat:` など) は付けない。
- 2 行目は空行。3 行目以降に詳細を `- ` の箇条書きで書く (変更理由や影響範囲など、差分だけでは分からないことを優先)。
- 関連 Issue がある場合は箇条書きに `#123` を含めてよい。
- 末尾にはシステムから指示された attribution 行 (Co-Authored-By など) があれば付ける。
- 複数行メッセージは HEREDOC で渡す:

```sh
git commit -F - <<'EOF'
ユーザープロフィール画面を追加

- ProfileScreen / ProfileContent / ProfileViewModel を追加
- 名前の保存に ProfileRepository を使用
EOF
```

## 禁止事項

- `--no-verify` や `--amend` は、ユーザーに指示されない限り使わない。
- push はしない (PR スキルで行う)。
