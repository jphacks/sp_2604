# JPHACKS 2026 ガイドライン

本チームは **札幌会場 sp_2604**(ブロックID `sp`、年度 `26`、チーム `04`)。

## 使い方

1. 全文は `references/guideline.md`(Notion 公開ページを Markdown 化したもの)。全体は約1300行なので、まず `grep -n '^# ' references/guideline.md` で見出しを確認し、該当範囲だけ読む。
2. 回答・判断は必ずガイドラインの記述を根拠にし、該当箇所(見出し名)を示す。記載がない事項は「ガイドラインに記載なし。運営事務局(Slack)に確認」と答え、推測で断定しない。
3. 情報が古い可能性があるとき、またはユーザーが更新を求めたときは再取得する:
   `python3 -I scripts/fetch_guideline.py ed99bc2d-28a7-8357-8aa4-014e0c554005 > references/guideline.md`
   (要ネットワーク: `jphacks-info.notion.site`)。原本: https://jphacks-info.notion.site/JPHACKS2026-ed99bc2d28a783578aa4014e0c554005

## 実装時に常に意識する要点

- **リポジトリはパブリック・MIT ライセンス**。API キー・トークン等の秘密情報をコミットしない。
- **審査で最重視されるのは動くデモ**。評価項目「完成度・動作性」は Hack Day 期間中の実装のみが対象。事前開発部分をメインの着眼点にしてはいけない。
- 使用技術そのものは評価対象外。問題解決に焦点。ハッカソン中に開発した技術は大きく評価。
- 持ち込み可能なのは「一般に誰でも入手できる公開データ・ソフトウェア・API・ライブラリ等」と運営/スポンサー提供物。第三者の知的財産権侵害は禁止。スポンサー提供物は提供条件に従う。
- **README.md** はテンプレートに沿って更新し、「デモ動画のリンク」と「作品情報」を必ず含める。審査開始(Hack Day 翌月曜 8:00)までに push/merge 完了。
- 提出フォームは Hack Day 2日目 15:30 まで(GitHub URL のみ受付)。
- 審査基準(各5点): 問題着眼点・着想点 / 実行・実現可能性 / 完成度・動作性 / プレゼンテーション力(Award Day のみ)。

詳細・最新の日時は必ず references で確認すること。
